Offline should mean no egress

Pointing inference at localhost solves the largest data path. It does not automatically silence everything else around the model.

17 August 2026·By 48Nauts·5 minute read

A gateway can send the prompt to a model running on the same machine and still make outbound connections. Provider heartbeats, health probes, model-catalogue refreshes and credit lookups often live on their own timers. If they continue running, “local model” and “offline system” are not the same claim.

NautGate treats offline mode as an operational state for the whole gateway. The provider heartbeat, probe scheduler and credits lookup stand down together while the local route keeps answering.

In a 70-second process socket sample, offline mode changed the gateway from a recurring remote connection to 127.0.0.1 only.

What the socket shows

With offline mode disabled, the sample saw a connection to 160.79.104.10:443, attributed to Anthropic, PBC, every 60 seconds. With offline mode enabled, only localhost remained and the local model continued serving calls.

The test matters because configuration labels are not proof. Sampling the process's actual sockets observes the boundary directly. The audit log then provides the complementary application-level record: the route, served model and data involved in each call.

Where local models fit

NautGate can address models in LM Studio and other OpenAI-shaped local servers. For self-contained work, a small local model can be surprisingly capable. Long multi-file agent loops are where frontier models still tend to pull ahead, and the KV cache has to be large enough to avoid repaying the harness cost on every turn.

A practical on-prem boundary

The result is a coding-agent setup that can run on hardware in your office, keep client code inside the building and retain a record showing what the gateway did. Local inference controls the destination. Offline mode controls the background. The audit trail makes both inspectable.
